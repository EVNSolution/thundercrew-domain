## 0. 확정된 결정 (문답 이력)

| 결정 | 내용 |
|---|---|

| 배차 완료 | **텔레메트리 자동 추정**이 주. 미연결 차량·오판은 수동 보정 |

| 알림 | 클리닝 임박/지연 → **운영자 사이트 벨**. 카톡 알림톡은 채널 등록 후 후속 |

| 라이더 등급 | **초보/고수 2단계** (중급 제거. 기존 데이터 전원 미판정이라 마이그레이션 부담 없음) |
| 직영/협력 | **계약 속성** (클리닝 계약 전용). 형태 변경 = 계약 갱신으로 이력화 |
| 충전소(BSS) | **제거** — 마커·탭·백엔드·테이블 전부 |
| 비핵심 | 화면 재편에 맞춰 적극 정리 (아래 §7) |

## 1. 정보 구조

```
[관제]   [배차]   [자원 관리]   [정비 관리]   [설정]
```

- **관제는 하나다.** 배송·클리닝을 화면으로 가르지 않는다 — 지도 하나에 전부 표시하고
  용도 토글로 거른다. 관제에서는 **개입만** 한다(완료 정정·재배정 바로가기). 등록·계획은
  전부 배차 화면에서.
- 왕복 배차·배민 콜 별도 섹션은 사라진다(§7).
- 시험용 SPA(`development/web`)의 레이아웃을 참고하되 구현은 운영 콘솔(Next.js)에 한다.

## 2. 관제 `/`

### 필터 바

```
[용도: 전체 | 배송 | 클리닝]   [권역: 단위(시▾) · 지역(수원시▾)]   [기존 차량 상태 필터]
```

- 기존 배차 방식 탭(콜/단일/순차/왕복/기타)은 **용도 토글로 교체**된다.
- **권역 필터**: 단위 select(광역/도/시/구, 기본 **시**) → 지역 select 가 그 단위의 목록으로
  바뀐다. 선택 시 지도 fit + 마커·하단 표를 GPS 좌표의 행정구역 경계 포함 여부로 필터링.
  - 경계 데이터: 공공 행정구역 경계(단순화 GeoJSON)를 프런트에 번들. 외부 API 없음.
  - **"권역 외 N대"** 카운터 표시(클릭 시 해제) — 필터로 숨은 차량이 "사라진" 걸로
    오해되지 않게 한다.
  - 좌표 없는 차량(텔레메트리 미수신)은 판정 불가 → **항상 표시**.
  - 마지막 선택은 localStorage. 계정 설정이 아니다.

### 선택 차량 보조 패널

- 배송 차량 선택 → 진행 중 배차 목록(현행 포커스 패널) + **완료 상태 배지**(자동/수동/추정 불가).
- 클리닝 차량 선택 → **오늘 일정 타임라인**(예정 시각순, 예상 도착, 지연 여부).
- 공통 개입: 완료 정정(수동 완료/되돌리기), 배차 화면의 해당 건으로 바로가기.

### 유지되는 것

지도 캔버스(MapLibre)·차량 마커·상태 칩·경로선·검색·팁 마커·알림 벨·플릿 시뮬레이션.
충전소 마커·탭은 제거(§7).

## 3. 배차 `/management/operations` 재편

### 배송 배차 (콜·단일 섹션 흡수)

- **등록 폼**: 고객명 · 연락처 · 주소(다음 우편번호 검색 → NCP 지오코딩) · 차량(직접 선택
  또는 시스템 자동 배정 — 현행 calls/system·offer 로직 재사용).
  - 지오코딩 실패 시 **지도에서 직접 핀 찍기** fallback(팁 미니맵 재사용).
  - **텔레메트리 미연결 차량 선택 시 경고** — "이 차량은 완료 자동 추정이 불가합니다".
- **모니터**: 현행 통합 모니터 유지 + 완료 상태 컬럼(`이동 중 → 도착 감지 → 완료(자동)` /
  `완료(수동)` / `추정 불가`) + 수동 완료·되돌리기·재배정·취소.
- 엑셀 대량 등록·내보내기 유지.

### 클리닝 배차 (순차 섹션 대체)

- **일별 일정표**: 날짜 선택 → 차량(클린차량)별 행에 시간축으로 배차 블록 표시.
- **시간 할당 폼**: 차량/클리너(활성 클리닝 매칭에서) · 고객 · 주소(동일 지오코딩) ·
  **서비스 예정 시각** · 소요시간(기본값은 설정에서).
  - 순번은 손으로 매기지 않는다 — **예정 시각순 자동**.
  - **충돌 검사**: 같은 차량의 시간 겹침(예정~예정+소요)은 등록 거부.
- **예상 도착** = 예정 시각 + 앞선 건들의 소요 누적. 실시간 위치 보정 ETA 는 후속
  (외부 OSRM 데모 서버를 운영 기능에 걸지 않는다).
- **알림**: 예정 임박(N분 전, 설정값)·지연(예정+소요 초과) 시 운영자 벨 알림 생성 —
  기존 알림 인프라(`notifications` + 벨) 재사용.

### 완료 자동 추정 (배송·클리닝 공통)

백엔드 스케줄러(기존 `MaintenanceAlarmEvaluator` 패턴)가 주기 평가:

```
목적지 반경 100m 진입 → 정지(시동 OFF 또는 저속) 3분 유지 → "도착 감지"
이후 반경 이탈                                            → COMPLETED (source=AUTO)
```

- 반경·정지 시간은 설정값으로 조정 가능하게 시작한다(현장 보정 전제).
- 텔레메트리 미연결 차량은 판정하지 않는다 → 모니터에 "추정 불가" + 수동 완료.
- 오판 정정: 수동 완료·완료 되돌리기(둘 다 감사 로그).

## 4. 자원 관리 `/management/resources` 재편

### 차량 — 행 클릭 상세 (신설)

| 섹션 | 내용 | 편집 |
|---|---|---|
| 기본 | 차량번호 · 용도 · 구분(2륜/4륜) · 연료(전기/내연/LPG) · 운영상태 | 인라인 수정 |
| 단말 | IMEI · 단말기 ID 연결/해제 (지도 화면 수정 폼 로직 이관) | 수정 |
| **함체** (배송용만 노출) | 부착 체크 + 부착일 — **장비(equipment) 도메인 재사용**: "함체" 장비 유형 시드, 부착/탈거 = 체크/해제, 이력 자동 | 체크 |
| **정비** | 품목별 상태(정상/임박/지연/기록 없음) + **교환 완료 체크** + 최근 이력 + 오입력 삭제 (지도 화면에서 이관) | 체크 |
| 매칭 요약 | 현재 계약(누구·형태·기간) + 매칭 섹션 바로가기 | 조회 |
| 텔레메트리 | 연결 · 시동 · 마지막 수신 한 줄 | 조회 |
| 이력 | 운영상태 변경 이력 (기존 미도달 API `bike-operation-status-histories` 연결) | 조회 |

- **차량 단건 등록 폼 부활** (현재 엑셀로만 가능): 차량번호·용도·구분·연료·운영상태·단말.

### 라이더 — 행 클릭 상세 (신설)

| 섹션 | 내용 | 편집 |
|---|---|---|
| 기본 | 이름 · 직무(라이더/클리너) · **등급(초보/고수)** · 연락처 · 팀 | 수정 |
| 교육 | 이수 상태 + 기록 목록 (기존 미도달 API 연결) | 수정 |
| 매칭 요약 | 배정 차량 · 계약 형태 | 조회 |
| 보험 메모 | 현행 자유 텍스트 2칸 유지 (지도 화면에서 이관) | 수정 |

- **라이더 단건 등록 폼 부활**.

### 매칭 — 생성 폼 부활 + 용도별 계약 형태

- 계약 형태가 용도에 따라 갈린다:

| | 배송(오토바이) | 클리닝 |
|---|---|---|
| 인수 방식 | 인수형/반납형 (현행) | — |
| 운영 형태 | — | **직영/협력** (신규 컬럼) |
| 구독/렌탈 | 현행 유지 | 해당 없음 |

- **반영 4곳**: ① 매칭 표(컬럼명 "계약 형태"로 통합, 용도별 값) ② 생성 폼(차량 선택 →
  용도가 폼을 가름) ③ **엑셀 템플릿·검증** ④ 백엔드 검증(어긋난 조합 거부).
- **교차 검증 신설**: 클리닝 계약 = 클린차량+클리너만, 배송 계약 = 배송용 차량+라이더만.
  폼에서 거르고 백엔드에서도 거부. (현행 명세의 "직무↔용도 일치 검증 없음" 구멍이 여기서 닫힌다.)

### 표 공통

- **검색·정렬** 추가 (현재 검색 없이 200건 1페이지).
- 모든 새 쓰기 경로에 감사 로그.

## 5. 정비 관리 `/management/maintenance`

- 카탈로그 화면 현행 유지.
- **버그 수정**: 생성·수정 서버 액션의 엔진 화이트리스트에 LPG 누락 — UI 에서 LPG 를
  골라도 조용히 걸러지는 문제 (`app/actions.ts` `MAINTENANCE_ENGINES`).
- km 주기 품목은 텔레메트리 미연결 차량에서 판정 불가 → 개월 주기 fallback 을 상세에 명시.
- 차량별 정비 **체크**는 자원 관리 차량 상세로 이동(§4). 정비 임박 알람(백엔드 스케줄러)은
  현행 그대로 벨로.

## 6. 설정 (신설 화면)

- **테마 색상**: 현행 라이트/다크 토글 + 액센트 색상 선택.
- **운영 기준값**: 클리닝 건별 소요시간 기본값 · 임박 알림 리드타임 · 완료 추정
  반경/정지시간.
- 권역은 여기 없다 — 관제 필터다(§2).

## 7. 정리 (제거/유지 목록)

### 제거

| 대상 | 범위 |
|---|---|
| **충전소(BSS)** | 지도 마커 · 하단 탭 · 필터 · Next 라우트 · 백엔드 컨트롤러/서비스 · `battery_stations`·`station_battery_count_logs` 테이블(마이그레이션, 사전 백업) |
| **왕복 배차** | 패널 · `dispatch_batches` 테이블 · batch 컨트롤러 · `DispatchOrderKind.PICKUP` (운영 사용 0건 확인됨) |
| 배민 콜 별도 섹션 | 배송 배차 등록 폼으로 흡수 (백엔드 calls/* 는 재사용) |
| `service_type` (계약) | 컬럼·enum 제거, `bikes.purpose` 로 단일화. 프런트 `ServiceType`·`isCleaningServiceType` → purpose 기반 치환 |
| 보험 상품·라이더 보험 CRUD | 백엔드 제거 (미도달). 라이더 **보험 메모 필드는 유지** |
| 단말 동기화 (`device-api-sync-runs`) | 백엔드 제거 (미도달, 사용처 없음) |
| 죽은 UI 18개 | 전부 삭제. 새 상세/폼은 새로 짠다 (죽은 코드는 참고만) |
| 계약 템플릿 CRUD | 미도달 쓰기(POST/PATCH/DELETE)만 제거. **읽기는 유지** (매칭 스냅샷이 구독/렌탈 판정에 사용 중) |

### 유지

팁(지도 보조, 실사용 중) · 교육(라이더 상세로 편입) · 엑셀 왕복 · 감사 로그 · 텔레메트리
수신 제어 · 플릿 시뮬레이션.

### 보류 (2차)

`next-customer` 계열(클리닝 시뮬이 읽는 중 — 시간 배차 정착 후 예정 시각순 유도로 대체) ·
클리닝 반복 일정 · 카톡 알림톡 · 실시간 위치 보정 ETA.

## 9. 구현 순서

| 단계 | 내용 | 배포 단위 |
|---|---|---|
| 1 | 정리(충전소·왕복·죽은 UI·미도달 백엔드) + 마이그레이션 전부 + LPG 버그 | 프리뷰 QA → 운영 |
| 2 | 자원 관리 재편 — 행 클릭 상세(정비·함체 체크) · 단건 등록 폼 · 매칭 폼(용도별 형태) · 검색 | 〃 |
| 3 | 배차 재편 — 배송 등록 폼 통합 · 클리닝 시간 할당·일정표 · 완료 자동 추정 · 알림 | 〃 |
| 4 | 관제 필터(용도 토글·권역) + 보조 패널 + 설정 화면(테마·기준값) | 〃 |

각 단계 끝마다 프리뷰 직접 배포 → QA → `main` 머지 → 운영 배포 → `dev` 동기화
(현행 방식 그대로).

## 10. 검증 기준 (요약)

- 자동 완료: 시뮬 차량으로 도착→이탈 시나리오 재현 시 COMPLETED(AUTO) 전환,
  미연결 차량은 "추정 불가" 표기.
- 클리닝 충돌: 같은 차량 시간 겹침 등록이 400 으로 거부.
- 계약 검증: 배송 차량+클리너 조합 생성이 폼·백엔드 양쪽에서 거부.
